# 天枢·低空智能运营管控平台
## Tianshu Low-Altitude Intelligent Operation & Control Platform

面向低空经济场景的一体化运营管控平台 —— 本科毕业设计
基于 Python Flask 和 Vue.js 的低空飞行管控平台的设计与实现

覆盖 **学生 / 商家 / 管理员** 三类角色，构建「申请 — 审批 — 调度 — 监控 — 结算」一体化闭环：
空域管理 · 飞行计划审批 · 无人机调度 · 实时监控回放 · 订单与结算 · 学情数据看板。

## 项目背景

低空经济作为国家战略性新兴产业，当前普遍存在 **空域资源管理分散、飞行审批流程繁琐、运营监控体系缺失** 三类问题。
传统的人工登记与分散式管理模式难以同时满足「安全管控」与「高效运营」的双重需求。

本项目设计并实现一个面向低空场景的智能运营管控平台，以
「计划申请 → 审批流转 → 资源调度 → 实时监控 → 结算对账」为主线，
用一套系统把学生、商家、管理员三类角色的业务流程串联起来。

## 快速开始

### 环境要求

| 依赖 | 版本 |
|------|------|
| Python | 3.9+ |
| Node.js | 16+（推荐 18/20） |
| MySQL | 8.0 |
| Redis | 6.0+ |

### 1. 初始化数据库

```bash
# 创建数据库并导入表结构与演示数据
mysql -u root -p < backend/sql/tianshu-ddl-v1.sql
# 可选：导入演示数据
mysql -u root -p tianshu < backend/seed/generate_mock_data.py
```

### 2. 配置并启动后端

```bash
cd 代码/backend

# 复制配置模板并填写自己的数据库账号
cp .env.example .env

# 编辑 .env，填入数据库用户名/密码与 JWT secret

# 安装依赖
pip install -r requirements.txt

# 启动后端
python run.py
```

后端启动于 http://127.0.0.1:5000。

### 3. 启动前端

```bash
cd 代码/frontend
npm install
npm run dev
```

前端启动于 http://127.0.0.1:5173，/api 已配置代理到 5000。

- 大模型 API Key 仅由后端持有并落库，查询接口脱敏为 `****后 4 位`，不下发前端。

## 接口约定

统一前缀 `/api`，除 `/api/auth/login`、`/api/auth/register` 外均需携带 `Authorization: Bearer <token>`；

统一响应体：
```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

| 业务码 | 含义 |
|--------|------|
| 0 | 成功 |
| 401 | 未登录 / token 失效 |
| 403 | 无权限访问该资源 |
| 1001 | 当前资源已关闭，请联系管理员 |
| 1002 | 参数校验失败 |
| 1003 | 用户名或密码错误 |
| 1101 | AI 服务未配置（管理端未填 API Key） |
| 1102 | AI 请求过于频繁（触发按用户维度的限流） |
| 1103 | 大模型密钥无效或已过期 |
| 1104 | 大模型账户余额不足 |
| 1105 | 被上游限流 |
| 1201 | 输入内容不合规（未调用大模型，直接拒绝） |

## 技术亮点

### 1. 三级 RBAC 权限模型
AuthInterceptor 负责「是否登录」，自定义装饰器 `@RequireRole` + 装饰器工厂负责「是否有权访问该方法 / 该类」，
配合 UserContext（g 对象）传递当前登录用户，实现方法级与类级双重校验。
前端请求层统一处理凭证：401 才清除 token 并跳登录，403 仅提示，避免越权提示误伤登录态。

### 2. 大模型能力的工程化封装
- **限流**：按 userId 维度的每分钟固定窗口限流器，超限抛出业务异常；
- **内容安全**：输入侧合规检测 + 生成内容的三重前置过滤（敏感词 / 未成年人适宜性 / 准确性），
  全量交互日志与教师人工复核兜底；
- **三级降级**：网络异常 / 超时 / 非 200 状态码统一捕获，降级返回预设文案；
  出题场景解析失败自动回退内置题库，保证第三方模型不可用时平台功能不中断；
- **密钥安全**：API Key 仅后端持有，管理端读取时脱敏。

### 3. 飞行进度闭环
课程视频通过 timeupdate 事件节流上报进度，后端取 max(已存进度, 本次上报) 保证只增不减（防刷分），
进度达到 100% 时反向将该学生对应的教师课程任务判定为完成，形成「观看 → 进度 → 任务完成」的可信闭环。

### 4. 前端工程质量
- 全站设计系统以 CSS 变量（Design Token）统一维护，改主题只改一处；
- 动画仅使用 transform / opacity，进度条用 scaleX() 规避布局重排；
- 路由懒加载 + 权限路由守卫，未登录用户无法直接访问后台页面。

### 5. 经验值与等级体系（账本制 + 幂等）
- **账本为唯一真相**：新增 exp_log 流水表，总经验 = SUM(exp)，而非按当前状态实时推导 ——
  因此删除作品、老师撤销批改都不会让经验倒退；
- **幂等**：(student_id, source_key) 唯一约束，同一件事重复触发只记一次，重复提交 / 重复上报不会刷分；
- **防刷**：单日经验上限 300，且所有加分只在后端业务动作里触发，不对外暴露「加分接口」；
- **递增曲线**：need(n) = 100 + 50×(n-1)，而非每级恒定值，后期升级有成长感；称号 6 档；
- **可解释**：学生能查看自己的经验明细流水（GET /api/exp/log），只返回本人的数据。

### 6. 账号安全
- 修改密码须校验原密码，长度 8~32 位且同时含字母与数字；同一用户 15 分钟内失败 5 次即锁定，防在线暴力破解；
- 失败文案统一为「原密码不正确」，不区分账号是否存在，避免账号枚举；
- 改密成功后写入 password_changed_at，鉴权拦截器拒绝签发时间早于它的 token —— 改密即等价于下线所有旧设备；
- 密码散列字段标注 @JsonIgnore，避免随用户信息接口下发前端。

### 7. 内容安全：面向未成年人的全链路审查
实现「输入检测 → 生成前置过滤 → 自动拦截 → 人工复核兜底 → 日志审计追溯」的完整闭环。

**三层过滤各司其职：**

| 层 | 判定方式 | 处置 |
|----|----------|------|
| 敏感词过滤 | 硬规则：只对词库中 level=3 的明令禁止词生效 | 非黑即白，命中即拦 |
| 未成年人适宜性评估 | 程度判断：全部命中词按分类权重累加，叠加站外导流特征分 | ≥80 拦截；30~79 放行但进复核队列 |
| 准确性校验 | 生成质量：结构完整性 + 数值型常识比对 | 过短替换；常识疑点放行转人工 |

分层的关键在于避免「一个词就误杀」：单独出现「暴力」不拦（风险分 60），
但同时出现「暴力 + 迷信」才拦（105 → 封顶 100）。词库的 category 字段同时充当打分权重来源。
